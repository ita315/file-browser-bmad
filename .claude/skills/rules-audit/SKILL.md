# rules-audit

## המטרה

לבדוק את הקוד מול כל AD ב-`ARCHITECTURE-SPINE.md` וכל כלל ב-`.claude/rules/`, ולדווח. בלי לתקן ובלי להציע תיקון, אלא אם המשתמש ביקש.

## מלכודות

1. **רק לקרוא.** לא להוסיף, למחוק או לערוך שום קובץ, גם לא ב-scratchpad או בתיקייה זמנית. בלי קובצי ניסוי, בלי `git archive` ובלי `git worktree`.
   - **החריג היחיד:** `npm run check`, שרץ פעם אחת בתוך `scripts/audit.sh`. הוא עלול לכתוב קובצי cache, והטסטים עשויים ליצור ולמחוק תיקייה זמנית. הסקריפט משווה את `git status` לפני ואחרי ההרצה.
2. **לקרוא רק קבצים בתוך הפרויקט**, בלי חריגים, כדי שהבדיקה תעבוד גם על מחשב אחר. בלי `~/.claude`, בלי תיעוד שיחות ובלי זיכרון מסשנים קודמים כראיה. אם הכלי שמר פלט ארוך מחוץ לפרויקט, לא קוראים את הקובץ הזה: מריצים `--section` על החלק הדרוש.
3. **מה שנדחה ב-triage עם נימוק לא נחשב הפרה.** רושמים את מספר הדחייה בעמודת ההערה. ממצא כזה נחשב הפרה רק אם הקוד השתנה כך שהנימוק כבר לא נכון, ואז כותבים מה השתנה. שורה עם route ‏`patch` או רישום ב-`deferred-work.md` הם לא דחייה.
4. **להריץ את `audit.sh` ישירות, בכל קריאה, ולא דרך משתנה.** כותבים בכל פעם את הפקודה המלאה `bash .claude/skills/rules-audit/scripts/audit.sh --section '...'`. ב-zsh, משתנה כמו `A="bash .../audit.sh --section"` לא מתפצל למילים, ו-`$A` נכשל עם `no such file or directory`.

## הצעדים

1. מריצים פעם אחת, משורש הפרויקט:
   ```sh
   bash .claude/skills/rules-audit/scripts/audit.sh
   ```
   הסקריפט מדפיס ראיות ולא פוסק: לכל בדיקה את מספר הממצאים בסוגריים ואת השורות הראשונות. אם הוא יצא עם קוד 2, חסר משהו להרצה: מדווחים על זה ועוצרים (ראו [`scripts/README.md`](scripts/README.md)). אם החלק `WORKTREE` אומר `CHANGED`, מציינים את זה בראש הדוח.

   הפלט מקוצר, ולכן אין להסיק ממנו שאין עוד ממצאים. בכל בדיקה שיש בה הפניה ל-`--section` (שורות נוספות או שורה שנחתכה), ולפני שפוסקים על הכלל שלה, מציגים אותה במלואה. זה לא מריץ שוב את `npm run check`:
   ```sh
   bash .claude/skills/rules-audit/scripts/audit.sh --section 'כותרת הבדיקה'
   ```
2. קוראים את [`references/rules-checklist.md`](references/rules-checklist.md) ואת הנוסח המלא של כל AD ב-spine ושל כל קובץ ב-`.claude/rules/`. אם יש סתירה, הנוסח של ה-spine או של הכלל גובר על ה-checklist.
3. עושים בעצמכם את בדיקות שיקול הדעת שה-checklist מפרט:
   - קריאת הקוד מול נוסח ה-AD, ובמיוחד AD-3, ‏AD-5, ‏AD-6 ו-AD-8. הסקריפט לא יכול לזהות מי מחליט על I/O או מי מחליט מה מוצג.
   - השוואת טוקני ה-typography מול `DESIGN.md`.
   - קריאת סדר ה-commits מול הכלל על ה-spike.
   - כשמשהו הוא הפרשנות שלכם ולא עובדה, כותבים את זה בעמודת ההערה.
4. מצליבים כל ממצא מול הדחיות (מלכודת 3). לכל spec יש חלק `triage rejections: <spec>`, ומציגים במלואו כל חלק שיש בו הפניה ל-`--section`, או כל החלקים יחד, עם `--section 'triage rejections'`. אם הפלט ארוך מדי, עוברים spec אחרי spec.
5. פותחים כל `קובץ:שורה` שאתם מצטטים ומוודאים שזו באמת השורה הנכונה.
6. כותבים את הדוח בשיחה בלבד, בלי לשמור אותו לקובץ:
   - טבלה עם ארבע עמודות בדיוק, ושורה אחת לכל כלל שמופיע בחלק `rules`:
     ```md
     | הכלל | תוצאה | קובץ ושורה | הערה |
     |---|---|---|---|
     | AD-1 | עובר | | |
     | AD-2 | נכשל | `src/lib/source.ts:31`, `src/lib/state.ts:86` | מה נשבר |
     | check-green-every-commit | נכשל | `35203cb:mcp_servers/design-tokens/tokens.test.ts:11` | כשל ב-commit ישן |
     | review-known-rejections | לא ניתן לאימות | | למה אין ראיה בפרויקט |
     ```
   - התוצאה היא בדיוק `עובר`, ‏`נכשל` או `לא ניתן לאימות`.
   - בעמודת הקובץ כותבים נתיב מלא מהשורש לכל מיקום, בלי קיצור כמו `:15`. כשל ב-commit ישן נכתב `sha:נתיב:שורה`.
   - אחרי הטבלה: אילו צעדים היו מכניים, אילו היו שיקול דעת, ומה לא נבדק.
7. בודקים את הדוח (הצעד הבא).

## בדיקת הדוח לפני שאומרים גמור

מעבירים לסקריפט את הטבלה בלבד, דרך pipe ובלי ליצור קובץ:

```sh
printf '%s\n' '<הטבלה>' | bash .claude/skills/rules-audit/scripts/audit.sh --validate
```

אם יש גרש בתוך הטבלה, כותבים אותו ב-shell כ-`'\''`.

הסקריפט בודק שכל כלל מופיע פעם אחת בדיוק עם תוצאה מותרת, שכל `נכשל` כולל `קובץ:שורה` שקיימים בתוך הפרויקט, ושכל `לא ניתן לאימות` כולל סיבה. אם הוא מדפיס `INVALID`, מתקנים את הדוח ומריצים `--validate` שוב. הוא לא מריץ שוב את `npm run check`.

## מתי גמור

- `--validate` הדפיס `VALID`.
- כל שורת `נכשל` נפתחה ונבדקה (צעד 5).
- ממצא שנדחה ב-triage לא נספר כהפרה, אלא אם הנימוק שלו כבר לא נכון.
- לא נכתב ולא נמחק שום קובץ מלבד החריג של `npm run check`, והחלק `WORKTREE` תועד בדוח.
- הדוח אומר במפורש מה לא נבדק. לפחות: שחוקי האכיפה באמת תופסים הפרות (נבדק רק שהם כתובים בתצורה), ו-`npm run check` על commits ישנים (נבדק רק HEAD).
