# audit.sh

## מה צריך להתקין

| מה | למה | בדיקה |
|---|---|---|
| Node.js 24.15 ומעלה, עם npm | `npm run check` (המינימום ב-`package.json`) | `node --version` |
| התלויות של הפרויקט | `tsc`, ‏`oxlint`, ‏`stylelint`, ‏`vitest` | להריץ פעם אחת `npm ci` בשורש הפרויקט |
| git | שורש הפרויקט, סטטוס והיסטוריה | `git --version` |
| bash (גם 3.2, שמגיע עם macOS) | מריץ את הסקריפט. לא zsh | `bash --version` |

לא צריך python, ‏ripgrep או חבילות גלובליות. הכלים `grep`, ‏`sed`, ‏`awk`, ‏`tr`, ‏`cksum` ו-`wc` מגיעים עם המערכת. הסקריפט עצמו לא מתקין כלום: אם משהו חסר, הוא יוצא עם קוד 2 ואומר מה חסר.

## איך מריצים

מכל מקום בתוך הפרויקט:

```sh
bash .claude/skills/rules-audit/scripts/audit.sh
```

| קוד יציאה | משמעות |
|---|---|
| 0 | הריצה הסתיימה. הפלט הוא ראיות, גם אם `npm run check` אדום או שיש ממצאים |
| 1 | `git status` השתנה במהלך הריצה (החלק `WORKTREE`) |
| 2 | חסר משהו להרצה, או ש-`--section` לא מצא כותרת מתאימה |

הפלט מקוצר בכוונה, כדי שלא יישמר מחוץ לפרויקט: לכל בדיקה מספר הממצאים בסוגריים, עד 5 שורות ועד 160 תווים בשורה. הגבולות נמצאים ב-`SHORT_LINES` וב-`SHORT_WIDTH`. כשמשהו מוסתר, בין אם שורות שלמות ובין אם סוף של שורה, הפלט מפנה ל-`--section`. רשימת הכללים, תוצאת `npm run check` ו-`WORKTREE` לא מקוצרות.

כדי לראות בדיקה במלואה, בלי להריץ שוב את `npm run check`, מעבירים טקסט מהכותרת שלה:

```sh
bash .claude/skills/rules-audit/scripts/audit.sh --section 'AD-11: describe without FR-'
```

בדיקת הדוח מקבלת את הטבלה דרך stdin, לא מריצה את `npm run check`, ומחזירה 0 על `VALID` ו-1 על `INVALID`:

```sh
printf '%s\n' '<הטבלה>' | bash .claude/skills/rules-audit/scripts/audit.sh --validate
```

## מה הסקריפט כותב

הסקריפט משתמש רק בפקודות קריאה, בלי הפניה לקובץ ובלי קבצים זמניים.

**החריג היחיד הוא `npm run check`.** ‏`tsc -b` ו-vitest עלולים לכתוב קובצי cache, וטסטים של `mcp_servers/` עשויים ליצור ולמחוק תיקייה זמנית של המערכת. כדי לתפוס שינוי בפרויקט, הסקריפט משווה את `git status` ו-checksum של `git diff` לפני ואחרי ההרצה. ההשוואה לא רואה קבצים ש-git מתעלם מהם, ולא שינוי בתוכן של קובץ untracked שכבר היה קיים.
